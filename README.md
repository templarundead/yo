# YOL — «Ё лайт»

**YOL** — программа для [ёфикации](https://ru.wikipedia.org/wiki/Ёфикация) русских
текстов: расстановки буквы «ё» там, где она подразумевается, но не написана.

Это полный перепис оригинальной программы на Delphi 7 (исходники оригинала
сохранены в каталоге [`legacy/`](legacy/)) на **Rust** с графическим
интерфейсом на **egui/eframe**.

```
┌──────────────────────────────────────────────────────────────────────┐
│ Файл  Правка  Ёфикация  Настройки  Помощь          слов: 140324 · …  │
├──────────────────────────────────────────────────────────────────────┤
│ [Ёфицировать] [Стоп] │ ✔ Рег. выражения  ☐ Только безопасные  …      │
├───────────────────────────────┬──────────────────────────────────────┤
│ Исходный текст                │ Результат (ёфицированный)            │
│                               │                                      │
│  Актер вышел на сцену…        │  Актёр вышел на сцену…               │
│                               │                                      │
├───────────────────────────────┴──────────────────────────────────────┤
│ Выберите вариант замены:  вс[ Е (1) ] / [ ё (2) ] таки               │
│ [Всегда Е (3)] [Всегда Ё (4)] [Откат] [Прервать (Esc)]               │
├──────────────────────────────────────────────────────────────────────┤
│ готово · заменено 12     12=12+0  A:0=0+0  RE:0=0+0  REQ:0.0%  …     │
└──────────────────────────────────────────────────────────────────────┘
```

## Что нового по сравнению с оригиналом

| | Оригинал (Delphi 7) | Этот порт |
|---|---|---|
| Платформы | только Windows x86 | Linux (x86_64 / ARM64), Windows, macOS |
| Зависимости | Windows RichEdit, `yo.ini`, `yox.dat`, `yo_regexpr.dat` | **ничего** — оба словаря внутри `.exe` |
| Отрисовка | GDI | WGPU (Vulkan / GL / Metal / DX12), фолбэк на OpenGL |
| Темы | системная | тёмная по умолчанию (`ctx.set_visuals(Visuals::dark())`) |
| Большие файлы | подвисает | фоновый поток + `mpsc`, результат потоково, без фризов |
| Редактор | один RichEdit | две панели «исходник / результат» с перетаскиваемым разделителем |
| Рег. выражения | `TRegExpr` (свой велосипед) | крейт `regex` (DFA, Unicode) |
| Консоль | — | файл → файл любых объёмов, потоково |
| Диалоги файлов | WinAPI | встроенный, на `std::fs` (без GTK/Qt) |

Алгоритм при этом **портирован один в один**: те же функции `ToYe`, `Cmp`,
`CopyCase`, `FindInStringsUL`, `SelectWord`, `MakeValidRegExpr`,
`MatchRegExp`, те же флажки и тот же формат строки состояния.

## Быстрый старт

```bash
git clone https://github.com/templarundead/yo && cd yo
cargo build --release            # → target/release/yol
./target/release/yol             # графический интерфейс
```

Подробные инструкции по сборке под Debian/Ubuntu, Alpine, ARM64
(Orange Pi 5+ / RK3588) и Windows — в **[BUILD.md](BUILD.md)**.

## Использование

### Графический интерфейс

```bash
yol                     # просто запустить
yol --gui               # то же самое, даже если переданы файлы

# По умолчанию рисует WGPU (Vulkan / Metal / DX12). На машинах без Vulkan
# (некоторые ARM-платы, старые драйверы, виртуалки) переключитесь на OpenGL:
YOL_RENDERER=glow yol
```

* **Верхняя лента** — главная кнопка «Ёфицировать» и все флажки ёфикации.
* **Слева** — исходный текст, **справа** — результат. Разделитель между
  панелями можно тянуть мышью.
* **Снизу** — панель запроса (в интерактивном режиме) и строка состояния со
  статистикой в формате оригинала.
* `Файл → Загрузить текст…` / `Сохранить результат…` — встроенный диалог с
  выбором кодировки (UTF-8 / UTF-8+BOM / UTF-16 LE / UTF-16 BE / Windows-1251).

### Консольный режим

```bash
yol -i текст.txt                     # результат в stdout
yol -i текст.txt -o ёфицированный.txt
cat текст.txt | yol > результат.txt
yol --version
```

Режим потоковый: исходник читается целиком (для 100 МБ это ≈100 МБ памяти),
а результат пишется порциями по 64 КБ, поэтому **файлы любого размера
обрабатываются без роста потребления памяти**.

Полный список ключей — `yol --help`.

## Как это работает

### 1. Встроенные словари

```rust
const DICTIONARY_BYTES: &[u8] = include_bytes!("../assets/yox.dat");
const REGEXPR_BYTES:    &[u8] = include_bytes!("../assets/yo_regexpr.dat");
```

Файлы попадают в бинарник на этапе компиляции. Во время работы диск больше
не читается вообще. Обе базы — в CP1251 (как в оригинале) и один раз
перекодируются в UTF-8.

| База | Записей | Что внутри |
|---|---|---|
| `yox.dat` | 140 324 | слова с «ё»; запись `слово?` означает «вариант спорный, спросить» |
| `yo_regexpr.dat` | 94 | контекстные правила («все, кто» → «всё, что», «перед \w+м» → «перед \w+м» …) |

### 2. Словарь

База хранится тремя параллельными массивами: `ye` (е-форма), `yo` (ё-форма) и
`lc = LC(ye)` — заранее посчитанный ключ поиска. Поиск — бинарный, по функции
`Cmp` оригинала: сначала сравниваются нижние регистры, при совпадении —
точное написание. Ищется `RestLowerCase(слова)`, затем `LC(слова)` — так
«Ёлка» и «ёлка» находятся одной и той же записью.

На горячем пути **ни одной аллокации**: все строки-буферы движка
переиспользуются.

### 3. Регулярные выражения

Правило из `yo_regexpr.dat` разворачивается функцией `MakeValidRegExpr`:

| Было | Стало | Зачем |
|---|---|---|
| пробелы | `\s+` | переносы и лишние пробелы |
| `е` / `ё` | `([ёе])` | **группа**: потом подставляем именно ту букву, что в словаре |
| `-` | `-(\r\n){0,1}` | перенос внутри слова |
| края-буквы | `\b` … `\b` | границы слова |

Дальше `MatchRegExp` находит совпадение в контексте (±2 слова вокруг),
подставляет в захваченные группы «правильные» е/ё из исходной строки правила
и смотрит, получился вариант с «е» или с «ё».

### 4. Конечный автомат `SelectWord`

Портирован построчно с `TMainForm.SelectWord`:

```
Word1 := ToYe(слово)                       ← вариант с «е»
Word2, ToAsk, Focus := FindReplacement()   ← то, что в словаре
ToAsk |= сокращение? | оборвано? | имя собственное?
WrongYo    := в слове «ё», а в словаре другая «ё»
ReplacedYo := WrongYo и в словаре есть вариант
WrongYe    := «е» меняем на «ё» без подтверждения
… «только безопасные», регулярные выражения, «всегда подтверждать» …
```

Отличие ровно одно: в оригинале неоднозначное слово **всегда** требовало
нажатия кнопки. Здесь это настраивается списком **«Неоднозначные»**:

* `Ставить Ё` — по умолчанию, обычная пакетная ёфикация;
* `Оставить Е` — консервативный режим;
* `Спрашивать` — интерактивный режим, внизу появляется панель запроса с
  кнопками «Е (1)» / «Ё (2)» / «Всегда Е (3)» / «Всегда Ё (4)» / «Откат» /
  «Прервать (Esc)».

### 5. Статистика

Строка состояния — точная копия формата Delphi-версии:

```
12=12+0  A:0=0+0  RE:2=2+0  REQ:66.7%  E:0  T:0.01  S:1200
│  │  │     │  │     │  │       │       │     │      └─ замен в секунду
│  │  │     │  │     │  │       │       │     └─ время, с
│  │  │     │  │     │  │       │       └─ подозрительных «ё»
│  │  │     │  │     │  │       └─ качество словаря рег. выражений, %
│  │  │     │  │     │  └─ РВ без результата
│  │  │     │  │     └─ РВ с заменой
│  │  │     │  └─ неоднозначных, оставлено как есть
│  │  │     └─ неоднозначных, изменено
│  │  └─ проверено, оставлено как есть
│  └─ проверено, изменено
└─ проверено слов с е/ё
```

Окно «Помощь → Статистика…» показывает те же счётчики по-человечески.

## Архитектура

```
src/
├── main.rs       — GUI (eframe/egui), фоновый поток, консольный режим
└── yo_core.rs    — словари, движок, статистика, кодировки (без GUI)

assets/           — yox.dat, yo_regexpr.dat (встраиваются в бинарник)
legacy/           — исходный код оригинала на Delphi 7
Cargo.toml        — профиль release: lto=true, opt-level=3, codegen-units=1
```

Главный поток **никогда** не ждёт рабочий:

```
┌──────────── главный поток (egui) ────────────┐       ┌── рабочий поток ──┐
│  YoApp::update()                             │  mpsc │                   │
│    ├ pump(): забирает Event из канала     ◄──┼───────┤  Engine::process  │
│    ├ рисует панель запроса                   │       │   через GuiSink   │
│    └ ans_tx.send(AskDecision) ───────────────┼──────►│  (стоит на ответе)│
└──────────────────────────────────────────────┘       └───────────────────┘
```

## Производительность

* **Холодный старт.** Словари (1.8 МБ) разбираются в отдельном потоке,
  запущенном из `YoApp::new` — окно появляется, не дожидаясь их. До первого
  кадра — единицы миллисекунд; полная готовность базы ≈25 мс на x86_64.
* **Обработка.** Порядка 10–30 МБ/с на ядро в зависимости от «плотности» слов
  с е/ё. В горячем цикле нет аллокаций: слово накапливается в переиспользуемый
  `String`; буферы нижнего регистра и «е-формы» — тоже переиспользуемые.
* **Память.** Результат держится в буфере 64 КБ и сбрасывается приёмнику;
  в консольном режиме пишется сразу в `BufWriter`, то есть текст целиком в
  памяти не хранится.

### Размер бинарника

Заявленные 3–5 МБ не достигаются: egui + winit + рендереры весят существенно.
Замер release-сборки под `x86_64-unknown-linux-gnu` (`lto = true`,
`opt-level = 3`, `codegen-units = 1`, `panic = "abort"`, `strip = true`):

| конфигурация | размер |
|---|---|
| по умолчанию: OpenGL + WGPU | **15.3 МБ** (15 265 760 Б) |
| `--no-default-features` — только OpenGL | **11.9 МБ** (11 857 728 Б) |

Из 15.3 МБ: `.text` — 9.5 МБ, `.rodata` — 4.2 МБ (в том числе 1.8 МБ
встроенного `yox.dat`). Что сделано для уменьшения:

* `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`;
* у `regex` отключены ненужные фичи (`unicode-age`, `unicode-bool`,
  `unicode-segment` …) — только `perf` + нужные классы;
* профиль `--profile minimum` (`opt-level = "z"`) для минимального размера;
* ни одного «тяжёлого» зависимого крейта: нет GTK, нет rfd, нет image-декодеров.

```bash
cargo build --profile minimum               # самый компактный бинарник
cargo build --release --no-default-features # без WGPU: −4 МБ, только OpenGL
```

WGPU — единственная опциональная фича (`renderer-wgpu`, включена по
умолчанию). Без неё приложение рисует через OpenGL, `YOL_RENDERER=glow`
продолжает работать в любой сборке, а `--profile minimum` и
`--no-default-features` можно сочетать.

## Тесты

```bash
cargo test --all              # юнит-тесты + интеграционные + док-тесты
cargo test --release --all    # то же в release (цифры ближе к боевым)
```

**Юнит-тесты** — в конце `src/yo_core.rs`: загрузка и сортировка словаря,
базовая ёфикация, сохранение длины текста, латиница и цифры как разделители,
флаг «Проверять ё», пропуск однобуквенных слов, преобразование регулярных
выражений, компиляция всех 94 правил, круговой проход CP1251, определение
кодировки, потоковая обработка 20 000 слов.

**Интеграционные тесты** — каталог `tests/`, работают с публичным API
библиотеки (`src/lib.rs`) и с настоящим собранным бинарником:

| Файл | Что проверяет |
|---|---|
| `tests/dictionary.rs` | целостность `yox.dat`: количество записей, строгая сортировка ключей, версия из шапки, известные слова (`актер` → `актёр`), регистронезависимость поиска, отсутствие выдуманных слов; все 94 правила скомпилировались и отметили позиции е/ё; сброс памяти ответов |
| `tests/yofication.rs` | движок целиком: замены, сохранение регистра (`CopyCase`), границы слов, все флажки вкладки «Ёфикация», интерактивный режим и отмена, политика для неоднозначных слов, правило «всё время», обход `<binary>` в FictionBook, статистика, пометки, журнал, потоковость и отмена на 400 КБ, `WriterSink` |
| `tests/encoding.rs` | распознавание UTF-8 / UTF-8+BOM / UTF-16 LE / UTF-16 BE, фолбэк на CP1251, круговой проход по всем пяти кодировкам, контрольные точки таблицы CP1251 |
| `tests/cli.rs` | настоящий бинарник: `--version`, `--help`, коды возврата (0 / 1 / 2), файл → файл, stdin → stdout, `--in-enc` / `--out-enc`, `--ambiguous`, отсутствующий файл |

## CI/CD

`.github/workflows/ci.yml` — двухстадийный пайплайн, запускается на push и PR
в `main` / `master` / `develop`:

**Stage 1 `lint-and-test`** (Ubuntu) — ставится stable-тулчейн с `rustfmt` и
`clippy`, ставятся системные GUI-зависимости (`libxkbcommon-dev`, `libxcb*`,
`libx11-dev`, `libwayland-dev`, `libgl1-mesa-dev`, `libgtk-3-dev`, `libssl-dev`),
кешируется `~/.cargo` и `target/` через `Swatinem/rust-cache`, затем:

1. `cargo fmt --all -- --check`
2. `cargo clippy --all-targets --all-features -- -D warnings`
3. `cargo test --all` и `cargo test --release --all`

**Stage 2 `build`** (`needs: lint-and-test`) — матрица
`x86_64-pc-windows-msvc` (windows-latest) и `x86_64-unknown-linux-gnu`
(ubuntu-latest), `cargo build --release` (в профиле `release` уже включены
`lto = true`, `opt-level = 3`, `codegen-units = 1`, `panic = "abort"`,
`strip = true`). Оба бинарника проходят дымовой тест (ёфикация контрольной
фразы) и выгружаются как артефакты `yol-windows-x86_64.zip` и
`yol-linux-x86_64.tar.gz`.

Дополнительно, не блокируя основной прогон (`continue-on-error`), собирается
статический ARM64-бинарник `cross build --target aarch64-unknown-linux-musl`
— тот самый, что нужен для Orange Pi 5+ / RK3588.
